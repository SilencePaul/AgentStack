# travel-helper 工作流验收

本轮使用 MM 派单、Qoder 团队开发/评审/测试、Leader 汇报和独立验收。所有改动在本地测试副本进行；没有向业务仓库推送，没有部署，也没有写入生产旅行数据。

## 计数原则

一轮对应一个实际问题。失败后的恢复、编译补修和只读复核仍属于原轮次，不能重复计数。团队报告与文件存在检查不足以证明业务完成：独立验证还要检查实际测试结果及任务结束时的源码快照。已完成轮次的历史结果不替代所有修改合并后的最终回归。

下面是截至 2026-11-06 的本地验收记录；原生 macOS 与生产环境的边界另列。

## 已执行的浏览器基线

Agent 交互测试实际执行 40 项通过，2 项是原测试设计中仅在 Chromium 验证 PNA 的用例、在 iPhone 跳过。覆盖确认授权、重复启动、取消、来源阻塞、恢复，以及本机 HTTP 与签名测试 transport。它不证明生产平台或原生 macOS Codex 执行器已通过验证。

日期相关的独立最终验收要求：实际应用配置的 TypeScript 检查、Overview 单元测试，以及原 3 个失败场景在 Chromium/iPhone 上各重复 2 次。不得用根配置空 `files` 的退出码替代应用类型检查，也不得通过延时、跳过或削弱断言消除失败。

## 最终组合回归与证据

本机 `.runtime/goal-validation/` 保存各轮任务、MM 回复线程、独立脚本和收据。`.runtime/goal-validation/final_local_gates.py` 等待全部轮次验收且项目空闲后，统一运行类型检查、lint、构建、contracts/web/backend/local/operations/地图相关测试，以及两组浏览器测试。源码前后变化、缺少 JUnit 或未获支持的跳过均不能计通过。

组合回归收据为 `.runtime/goal-validation/final-local-20261106-045150/receipt.json`，退出码 0，源码前后哈希均为 `5c318047f888a391a8825abf038756123123d6d0defb65bd71656370e59ffdfc`。实际结果：

- 类型检查、lint、完整构建成功；lint 仍有既有警告，不能称为零警告。
- contracts 121 项、Web 457 项、backend 125 项、本地脚本 18 项通过，无失败或跳过。
- operations、地图能力检查、POI 校验脚本均退出 0。
