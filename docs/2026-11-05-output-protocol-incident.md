# 2026-11-05：内网试运行输出协议故障复盘

## 证据与结论

依据：MM 内网试运行频道的任务结果、用户提交的现场排查摘要，以及 GitHub main 的实现。尚未直接读取内网 Windows 主机上的原始 stdout，因此 SDK 如何将文本转换成空调用、具体模型版本的归因仍需现场原始事件确认。

| 任务 | 观测到的问题 | 对照代码确认的行为 |
| --- | --- | --- |
| 0761317ed7be4bdd8ce3316ee8fc142f | lead-plan 输出模拟工具调用标签，缺少最后一行 PLAN 决策；进程 exit=0 | Leader 无工具；阶段需要有效决策才能进入 developer。进程正常退出不能替代协议校验。 |
| f00ab16a32f74fd8b4189510f7853f65 | developer 出现 Bash 缺少 command 的参数错误；进程 exit=0 | 工具错误会导致任务失败；开发阶段不会自动重放，避免重复执行已产生副作用的操作。 |

这不是“MM 没连通”导致的失败。任务已经进入执行阶段。模型输出、执行器调用协议和监督器阶段协议未完全契合，加上原有 Leader 没有协议错误分类与安全恢复，是这次可复现的薄弱点。不能仅凭现场摘要断言某个模型必然有问题。

## GitHub 新更新覆盖了什么

- `3515ced`：业务验收后才允许关闭工单；加强任务续跑绑定、只读阶段保护及总时间预算。
- `8c06431`：独立 `/diag report TASK [page]`，可提取脱敏的失败摘要和日志错误，不依赖重新调用 Qoder。

两项更新分别加强完成门槛和可诊断性，没有修复 Leader 模拟工具文本或缺少决策标记的问题。

## 本地补丁

1. 明确输出约定：工具只能走执行器原生调用接口；无工具 Leader 只做计划、分流和汇总。
2. 将 Leader 模拟工具调用文本与缺少有效决策分别记录为 `simulated_tool_markup`、`invalid_leader_decision`，保留原始失败证据。
3. 整个团队任务最多进行一次 Leader 协议重试。仅在进程正常退出、没有真实工具调用/错误/权限拒绝、没有原生异步代理、没有模型错误且工作区未变化时允许。使用新会话，沿用总截止时间；暂停问答续跑也不能重置次数。
4. 重试上下文不再复制异常调用文本，原文仍保存在证据中。持续异常则明确失败，不启动 developer，不伪造成功。
5. Bash 缺少 command 保持硬失败，并给出具体参数诊断。没有给 developer 增加自动重放。
6. Windows 目录隔离测试在缺少符号链接权限时使用真实目录 junction 验证越界保护，不跳过测试。

## 如何降低再次发生的概率、限制影响

- 每次更换执行器/模型/提示词/skill，先跑相同版本组合的只读冒烟；再检查真实工具事件、角色决策和独立验收，不只检查退出码。
- 团队成员模型来自项目的 `model`。`router_model` 用于目标规划，单改它不会切换团队执行模型。
- 运维记录主机、代码提交、Qoder 版本、项目模型和任务 ID。不同主机采用独立测试频道，避免把另一个运行实例的响应误认为本机结果。
- 异常时先读 `/diag report`，确认失败阶段与副作用，再决定续跑；诊断不应依赖再次启动一个开发任务。
- 保持业务验收门槛。文件存在、角色口头 PASS 和 Qoder exit=0 都不能单独证明业务完成。
- 后续可将 Leader 的文本终止标记升级成版本化结构化决策协议；这属于协议迁移，本补丁没有宣称已实现。

不能保证随机模型永不产生非法输出。可保证的目标是：已识别的非法输出不能直接推进流程；恢复次数和时间受限；失败有证据；开发副作用不会因该恢复机制被自动重放。

## 验证与部署边界

- 本地全量自动测试：156 项通过，包括协议错误恢复、次数上限、真实调用/权限拒绝/工作区变化时禁止重试，以及问答续跑后预算不重置。
- 本地真实 Qoder 冒烟（2026-11-05 23:18，启动记录模型为 Auto）：五个阶段完成；两个 Leader 阶段无工具调用，developer 调用 Bash，reviewer 调用 Bash/Read，tester 调用 Bash，工具错误均为零。未触发协议重试。未配置业务验收，最终正确保持 `reported_unverified`。该结果不能代替内网现场模型的复测；异常恢复由自动测试注入错误验证。
- 内网主机未在本轮升级或重启，原失败任务未自动续跑。必须在该主机部署补丁后，以相同执行器和模型做现场验证，才能认定内网故障已闭环。
